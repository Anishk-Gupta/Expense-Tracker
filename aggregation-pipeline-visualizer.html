MongoDB Aggregation Pipeline

Step-by-step visualization of how getExpenseSummary transforms data

DB

Raw Database (All Expenses)

MongoDB collection has 100,000 expenses from different users:

{ _id: "exp1", owner: "User_A", amount: 250, category: "Food", date: "2026-10-01" }
{ _id: "exp2", owner: "User_B", amount: 500, category: "Travel", date: "2026-10-05" }
{ _id: "exp3", owner: "User_A", amount: 1200, category: "Shopping", date: "2026-10-08" }
{ _id: "exp4", owner: "User_A", amount: 800, category: "Bills", date: "2026-10-02" }
{ _id: "exp5", owner: "User_C", amount: 300, category: "Food", date: "2026-09-30" }
... 99,995 more expenses ...
↓
1

Stage 1: $match (Filter)

{ $match: { owner: ObjectId("User_A") } }
What happens

MongoDB scans the owner index and instantly jumps to User_A's expenses. 99.9% of documents ignored!

Documents passing through (3 out of 100,000)

{ _id: "exp1", owner: "User_A", amount: 250, category: "Food", date: "2026-10-01" }
{ _id: "exp3", owner: "User_A", amount: 1200, category: "Shopping", date: "2026-10-08" }
{ _id: "exp4", owner: "User_A", amount: 800, category: "Bills", date: "2026-10-02" }
↓
2

Stage 2: $group (Calculate)

{ $group: { _id: null, totalSpent: { $sum: "$amount" }, avgExpense: { $avg: "$amount" }, maxExpense: { $max: "$amount" }, minExpense: { $min: "$amount" }, totalCount: { $sum: 1 } } }
What happens

_id: null means "put ALL documents in ONE bucket". Then MongoDB runs math operations on that single group.

Math in action

totalSpent = 250 + 1200 + 800 = 2250
avgExpense = (250 + 1200 + 800) / 3 = 750
maxExpense = max(250, 1200, 800) = 1200
minExpense = min(250, 1200, 800) = 250
totalCount = 1 + 1 + 1 = 3

Documents passing through (1 aggregated result)

{ _id: null, totalSpent: 2250, avgExpense: 750, maxExpense: 1200, minExpense: 250, totalCount: 3 }
↓
3

Stage 3: $project (Clean Up)

{ $project: { _id: 0, totalSpent: 1, avgExpense: { $round: ["$avgExpense", 2] }, maxExpense: 1, minExpense: 1, totalCount: 1 } }
What happens

_id: 0 removes the useless _id field. $round cleans decimal values to 2 places (750.333... → 750.00).

Final result sent to client

{ totalSpent: 2250, avgExpense: 750.00, maxExpense: 1200, minExpense: 250, totalCount: 3 }
✓

Performance Win

Without Aggregation: 100,000 docs → RAM → JavaScript loops → Slow (5-10 seconds)
With Aggregation: 100,000 docs → Index jump → 3 docs → Database math → Tiny result (20ms)

Database did all the heavy lifting. Only ~50 bytes traveled over the network instead of megabytes!
